# HID Desk — CH9329 + CH340 웹 키보드·마우스

기존 Web Virtual Keyboard의 독립 실행형 케이블 버전입니다. 2026-09-28에 추가되었습니다. ESP32 펌웨어를 케이블에 설치하지 않습니다.

## 실행

1. **이 폴더 전체를 유지**하고 `index.html`을 제어용 PC의 데스크톱 Chrome / Edge에서 직접 엽니다. 파일 더블클릭 시 다른 브라우저가 열리면 연결 프로그램을 지정하세요. 안드로이드 휴대폰은 [아래 안내](#안드로이드갤럭시에서-실행)를 따릅니다.
2. CH340 쪽 USB를 제어 PC에, CH9329 쪽 USB를 대상 PC에 연결합니다. 케이블의 표기와 판매자 설명으로 방향을 확인하세요.
3. 기본 속도 `9600`에서 **케이블 연결**을 누르고 CH340 시리얼 포트를 선택합니다. 판매자가 속도·주소를 변경했다면 해당 값을 사용합니다. 연결에 성공한 속도는 브라우저가 허용하면 기억되어 다음 실행 때 미리 선택됩니다.
4. 대상 PC에서 영문(US) 입력 상태, Caps Lock 끄기, 입력창 포커스를 확인하고 전송합니다.

**서버, npm 설치, 빌드, 인터넷, ESP32가 필요 없습니다.** 로컬 파일(`file://`)에서 일반 스크립트를 읽습니다. 외부 라이브러리·폰트·분석 서비스·네트워크 요청이 없습니다. 연결 허용은 사용자가 브라우저에서 직접 해야 하며 파일을 다시 열면 다시 선택해야 할 수 있습니다. 관리되는 브라우저에서 장치 접근을 막은 경우에는 사용할 수 없습니다.

“드라이버리스”는 **대상 PC의 HID 쪽**을 의미합니다. **데스크톱 제어 PC에는 CH340 시리얼 드라이버가 필요**하며 OS에 없으면 제조사 드라이버 설치가 필요합니다. 제어 PC의 COM 포트를 없애는 기능은 아닙니다. Safari, iPhone/iPad, 앱 내장 브라우저에서의 연결은 보장하지 않습니다. 화면이 표시되는 것과 Web Serial / WebUSB를 사용할 수 있는 것은 별개입니다.

## 안드로이드(갤럭시)에서 실행

안드로이드 Chrome의 Web Serial은 블루투스 시리얼만 지원하므로, 안드로이드에서는 **WebUSB로 CH340 칩을 직접 제어**합니다(`ch340-usb.js`). 별도 앱이나 드라이버는 필요 없습니다.

1. 이 폴더 전체를 **HTTPS 주소**(예: GitHub Pages)에 올리고 휴대폰 **Chrome**으로 엽니다. 휴대폰에서 로컬 파일로 열면 옆의 스크립트 파일을 읽지 못할 수 있습니다. 휴대폰 USB 포트는 OTG에 쓰이므로, 개발 중에는 무선 디버깅과 `adb reverse`로 PC의 로컬 서버를 `http://localhost`로 여는 방법도 있습니다.
2. OTG 젠더(USB-C ↔ USB-A)로 **CH340 쪽을 휴대폰에**, CH9329 쪽을 대상 PC에 연결합니다.
3. **케이블 연결**을 누르고 목록에서 CH340 장치(`USB Serial`, `USB2.0-Serial` 등)를 선택한 뒤 USB 사용 권한 요청을 허용합니다.
4. 이후 사용법은 데스크톱과 같습니다. 통신 속도·주소도 같은 값을 사용합니다.

- **장치 설정 → 연결 도움말 → 연결 방식**의 기본값은 “자동”입니다. 안드로이드에서는 USB 직접, 그 외 기기에서는 시리얼 포트를 사용합니다. 선택한 방식은 브라우저가 허용하면 기억됩니다.
- USB 직접 방식은 CH340/CH341만 지원합니다(Linux `ch341` 드라이버와 같은 장치 ID, 8N1 고정). CH343/CH9102, CP210x, FTDI 케이블은 지원하지 않습니다.
- 데스크톱에서도 USB 직접을 선택할 수 있지만, 운영체제의 CH340 드라이버가 장치를 먼저 사용하면 열리지 않습니다. 데스크톱은 시리얼 포트 방식을 사용하세요.
- 삼성 인터넷 등 다른 브라우저는 보장하지 않습니다. 화면이 꺼지거나 Chrome이 백그라운드로 가면 빠른 입력은 중단되므로 전송 중에는 화면을 켜 두세요.

## 포함 기능

- ASCII 텍스트 입력, Enter 추가, 빠른 연속 입력 / 호환 모드, 키 입력 간격, 시작 전 대기, 중지, 실제 초당 전송량 표시.
- Ctrl/Shift/Alt/Win, 기능 키와 조합키. Windows 한/영 전환은 오른쪽 Alt를 전송하며 IME 상태를 읽거나 고정하지 않습니다.
- 상대 이동, 좌·우·가운데 클릭, 더블 클릭, 휠, 절대 좌표 이동. 화면 캡처와 원격 화면 표시는 포함하지 않습니다.
- 텍스트·단축키 프리셋 저장 및 JSON 내보내기/가져오기. 기존 펌웨어의 숨김 프리셋과 달리 브라우저에 평문으로 저장합니다. 이 버전의 JSON 형식을 사용합니다.
- 기존 프로젝트와 호환되는 WVK1/WVK2 파일 전송, 자동 gzip 압축, CRC32/SHA-256 검증. 한글은 UTF-8을 Base64로 타이핑한 뒤 대상 디코더에서 복원합니다.
- 압축된 디코더 빠른 설치, 디코더 다운로드, 전체 HTML 소스 타이핑. 압축을 풀면 기존 프로젝트의 `web/decoder.html`과 바이트 단위로 동일하며 SHA-256도 확인합니다.
- CH9329 버전·USB 인식·Caps Lock·설정 읽기, 설정 백업, 4가지 동작 모드 선택·저장.

## 파일 / 한글 전송

대상 PC에 `decoder.html`을 준비해 브라우저로 엽니다. 파일을 직접 옮길 수 없으면 빈 일반 텍스트 편집기에 **빠른 디코더 타이핑**을 실행하고 `decoder.html`로 저장합니다. `.txt`가 덧붙지 않게 하세요. 압축 소스가 내장되어 인터넷 없이 현재 Chrome / Edge에서 전체 디코더로 펼쳐집니다. 전체 소스 타이핑은 해당 카드의 접힌 추가 옵션에 있습니다.

디코더의 데이터 입력창을 선택한 뒤 파일 복원 전송 또는 **디코더로 보내기**를 사용합니다. 전송이 끝나면 대상 디코더의 **검증하고 열기**를 눌러 원본을 확인합니다. 파일 전송의 실체는 많은 키 입력이므로 큰 파일은 오래 걸립니다. UI 예상 시간은 시리얼 바이트 수와 키 간격으로 계산한 하한선이며 USB와 브라우저 지연은 추가됩니다. 준비 가능한 크기는 16 MiB입니다.

원문 모드는 ASCII와 탭·줄바꿈만 지원하고 CRLF/CR은 Enter로 정규화합니다. 원문 전송 시 편집기의 자동 들여쓰기를 끄세요. 전송 중 다른 키 입력이나 포커스 이동이 있으면 내용이 달라질 수 있습니다.

## 전송 속도 높이기

1. 오른쪽 **입력 속도 → 빠르게**가 기본입니다. 추가 대기 시간을 0으로 하고 서로 다른 키가 같은 수정 키 상태로 이어지면 중간의 빈 키 리포트를 생략합니다. 같은 키 반복, Shift 변경에는 해제를 넣어 반복 입력과 대소문자를 유지합니다. 모든 리포트의 장치 응답을 확인합니다. 키 입력이 누락되는 대상 환경은 **호환**으로 바꾸고 5–10ms 간격을 사용하세요.
2. **장치 설정 → 케이블 전송 속도 올리기 → 57600 → 속도 저장**을 사용합니다. 현재 속도로 먼저 연결해야 합니다. 양쪽 USB를 뽑아 전원을 완전히 끊은 뒤 재연결하세요. 제어 화면의 연결 속도도 저장한 값으로 맞춰집니다. 이 값은 브라우저가 허용하면 저장되어 다음 실행에도 유지됩니다. 다른 케이블/초기화한 장치는 다시 9600을 선택하세요.
3. 115200은 CH9329가 **5V로 동작하는 것을 확인한 제품**에서만 사용하세요. WCH 문서상 3.3V CH9329에서는 지원하지 않습니다. 케이블에 USB 5V가 들어온다는 것만으로 내부 칩의 동작 전압을 확정할 수는 없습니다.
4. 디코더 최초 설치에는 **빠른 디코더 타이핑**을 사용합니다. 현재 원본 16,857자 대신 9,644자를 입력합니다. 빠른 입력을 함께 쓰면 이 디코더의 리포트 수는 33,715개에서 14,315개로 약 58% 줄어듭니다. 이는 계산한 전송량 감소이며, 실물에서 측정한 속도 배수는 아닙니다.

속도 저장은 현재 모드 번호를 보존하고 통신 모드를 프로토콜 모드 0으로 유지합니다. 설정 명령에는 소프트웨어 모드 값이 필요하므로 하드웨어 핀 기준이었던 모드도 **같은 번호의 소프트웨어 설정으로 고정**합니다. 주소·VID/PID·기타 설정을 보존하며 HID 기능 종류를 새로 선택하지 않습니다. 이후 모드를 핀으로 변경하는 용도라면 제조사 설정 도구로 전환해야 합니다. 기존 설정이 프로토콜 모드가 아니거나 형식이 다르면 저장을 거부합니다.

위쪽 연결 속도 선택만 바꾸면 CH9329의 속도는 바뀌지 않습니다. 장치에 저장하고 전원을 다시 연결하는 절차가 필요합니다. 빠른 입력에서는 불필요한 응답 확인을 없애거나 명령을 한꺼번에 보내지 않습니다. 전송 도중 탭을 숨기면 키가 눌린 채 지연되는 것을 줄이기 위해 중단하고 해제를 시도합니다. 전송을 마칠 때까지 이 탭을 열어 두세요.

## 전원을 넣을 때 적용할 동작 모드 선택

최초 설정은 대상 PC에 연결하기 전에 테스트 PC에서 진행합니다.

| 모드 | 대상 PC에서 인식되는 기능 |
| --- | --- |
| 0 | 키보드 + 마우스 + 사용자 정의 HID (공장 기본값) |
| 1 | 일반 USB HID 키보드만. 마우스·멀티미디어 키·사용자 정의 HID 제외 |
| 2 | 키보드 + 마우스. 멀티미디어 키 포함, 사용자 정의 HID 제외 |
| 3 | 데이터 통신용 사용자 정의 HID만. 키보드·마우스 제외 |

1. 케이블을 연결한 후 **장치 설정 → 설정 읽기**에서 정보를 확인하고 설정을 백업합니다.
2. **저장할 동작 모드**에서 원하는 모드를 선택합니다. 키보드만 필요하면 **모드 1**입니다. 제품 설명서에서 선택한 모드의 기능을 확인하세요. 특히 모드 2는 WCH 최신 데이터시트와 2019년 프로토콜 문서의 설명에 차이가 있어 자동 판단하지 않습니다.
3. 확인 항목을 체크하고 **모드 N 저장**을 누릅니다. 설정 50바이트를 다시 읽어 동작 모드를 선택한 0–3의 소프트웨어 설정으로, 시리얼 통신 모드를 0(프로토콜)으로 저장합니다. 주소·속도·VID/PID·기타 설정은 보존합니다. 알 수 없는 설정 길이와 범위 밖 모드는 거부합니다.
4. 저장 응답 후 연결이 닫힙니다. **양쪽 USB를 모두 뽑아 완전히 전원을 끈 다음 다시 연결**합니다.
5. 테스트 PC의 장치 관리자/USB 정보에서 처음 인식될 때부터 선택한 기능만 나타나는지 확인합니다. 제어 프로그램 없이도 확인하세요. OS가 USB 복합 장치나 여러 HID 항목으로 표시할 수 있습니다.

연결하거나 설정을 다시 읽으면 현재 동작 모드의 번호와 이름이 표시되고 선택란에도 반영됩니다. 모드를 새로 선택하면 확인 체크가 해제됩니다. 선택만으로 장치나 입력 기능이 바뀌지 않으며 저장·전원 재연결 후 읽은 모드가 기준입니다. 모드 1에서는 마우스 조작을, 모드 3에서는 키보드·마우스·파일 타이핑을 비활성화합니다. 모드 3에서도 설정 읽기·백업·동작 모드 변경은 가능하지만 사용자 정의 HID 데이터를 주고받는 UI는 제공하지 않습니다. 연결·연결 해제 시에도 현재 모드가 지원하는 입력 해제 명령만 전송합니다.

저장 성공 응답이나 모드 값 읽기만으로 실제 USB 인터페이스 구성을 검증할 수는 없습니다. **이 웹 화면에서 대상 PC의 USB 디스크립터를 읽거나 HID 전용임을 인증하지 않습니다.** 공장 초기화하면 저장 설정이 사라집니다. 소프트웨어는 시작할 때 모드를 자동 변경하지 않습니다.

## 통신과 오류 처리

- **`Failed to open serial port`**는 CH9329 응답을 확인하기 전, 제어 PC의 시리얼 포트를 여는 단계에서 발생합니다. 동작 모드 2나 속도 불일치로 단정하지 마세요. CH340 포트(`USB Serial`, Mac의 `cu.usbserial-*`)를 선택하고, 같은 포트를 사용하는 다른 탭·시리얼 프로그램을 닫은 뒤 양쪽 USB를 모두 분리·재연결하세요. 계속 실패하면 CH340 드라이버와 USB 연결을 확인합니다. 다른 장치의 `usbmodem` 포트나 Bluetooth 포트를 선택하지 않도록 주의하세요.
- **USB 직접 방식에서 `USB 장치를 열지 못했습니다`**가 나오면 USB 사용 권한 요청을 허용했는지, CH340 쪽이 휴대폰에 연결됐는지 확인합니다. 같은 장치를 쓰는 다른 탭·앱을 닫고 양쪽 USB를 분리·재연결하세요. 목록에 장치가 보이지 않으면 OTG 젠더와 케이블 방향을 확인합니다.
- **포트가 열린 뒤 장치 응답이 없으면** 저장된 속도·주소·시리얼 통신 모드와 양쪽 USB 연결을 확인합니다. 기본값은 9600 bps / 주소 0이며, 이전에 속도를 저장했다면 그 값을 사용합니다. 동작 모드 저장은 속도를 변경하지 않습니다. 화면의 연결 오류 안내는 다음 연결 시도까지 유지됩니다.
- 8N1, 흐름 제어 없음, 기본 주소 0. 프로토콜 모드(시리얼 모드 0)가 필요합니다. ASCII/투명 모드로 출고됐다면 제조사 도구/설정 핀으로 먼저 변경해야 합니다.
- 한 명령마다 체크섬과 응답을 확인하고 다음 명령을 보냅니다. 동시 작업은 막습니다.
- 호환 모드는 글자마다 누름·해제를 보냅니다. 빠른 모드는 다음 키 리포트로 이전 키를 해제하며, 반복/수정 키 전환과 종료에는 별도 해제를 보냅니다. 중지는 진행 중 응답을 기다린 뒤 키를 해제합니다. 전송 도중 탭을 닫지 마세요.
- 응답 시간 초과·연결 끊김에는 해당 연결을 사용 불가로 표시하고 전송을 중단합니다. 같은 입력 명령을 자동 재전송하지 않습니다. 재연결 시 USB가 인식되어 있으면 키와 버튼 해제를 시도합니다.
- 재개는 지원하지 않습니다. 일부 입력이 이미 전달됐을 수 있으므로 대상 내용을 비우고 처음부터 다시 보내세요.
- 장치의 응답은 대상 응용 프로그램의 문자 수신 확인이 아닙니다. 파일은 디코더의 CRC/SHA 검증을 최종 기준으로 사용합니다.

## 파일 구성과 검증

`index.html`, `styles.css`, `app.js`, `protocol.js`, `ch340-usb.js`, `transfer.js`, `decoder-source.js`가 제어 화면입니다. `ch340-usb.js`는 안드로이드용 CH340 WebUSB 드라이버입니다. `decoder.html`은 대상 PC용이며 `decoder-installer.html`은 압축된 설치용 HTML입니다. 런타임에는 빌드가 필요하지 않습니다.

디코더 원본을 수정한 개발자는 `node ch9329-web/scripts/build-decoder.cjs`로 두 디코더와 내장 소스를 다시 생성합니다.

개발 검증: `node --test ch9329-web/tests/*.test.cjs` (저장소 루트에서 실행).

프로토콜 프레임·단편화·오류·타임아웃·설정 보존, 키코드, CH340 WebUSB 초기화·통신 속도 레지스터·분리 처리, 기존 디코더와 WVK1/WVK2 왕복 검증을 포함합니다. 자동 검증의 가상 시리얼·USB 장치는 실제 하드웨어 테스트를 대체하지 않습니다.
