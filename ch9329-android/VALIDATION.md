새 프로토콜 검사는 WCH `0x0A` 응답의 종류·길이(0–23바이트), 빈 문자열과 최대 길이, 분할 응답, 잘못된 응답 형식, 지원하지 않는 명령, `0x0B` 문자열 저장과 `0x09` 사용 비트 저장의 순서를 확인합니다. 제조사명·시리얼 번호를 개별 사용/해제하는 조합에서 제품명 사용 상태와 예약 비트, VID/PID·주소·속도·기타 설정을 보존하는지 검사했습니다. 모든 입력을 검증하기 전에는 저장 명령을 보내지 않으며, 장치 거부·응답 시간 초과 이후의 재전송과 추가 쓰기가 없는지 확인했습니다.

DOM 검사는 실제 배포 자산을 native IPC 가상 장치에 연결합니다. 현재 값 읽기, 기본값 사용, 잘못된 입력 거부, 저장 중 입력 잠금, 각 저장 ACK, 재연결·재조회, JSON 백업, 중간 저장 실패 안내와 실제 저장값 재조회, 미지원 문자열 조회 후에도 일반 키보드를 사용할 수 있는지를 확인했습니다. 기존 텍스트·한글·마우스·압축 파일·UTF-8 변경분·프리셋·USB 분리 시나리오도 통과했습니다.

공유 웹 소스에서 안드로이드 자산과 `upstream/` 스냅샷을 생성하므로, 공통 설정 UI와 프로토콜 구현은 웹 버전에도 반영됩니다. 별도 안드로이드 폴더에서도 같은 소스로 재생성할 수 있습니다.

## 검증 한도와 설치

실제 갤럭시·CH340/CH9329 케이블은 연결되어 있지 않습니다. USB 권한창, Android WebView, 문자열의 실제 비휘발성 저장, 전원 재연결 후 대상 OS에 표시되는 정보는 실기기에서 확인해야 합니다. DOM 검사는 렌더링 레이아웃 검사가 아닙니다. 별도 Chromium 시각 검사는 실행 환경에서 브라우저 시작이 실패하여 완료하지 못했습니다. Gradle 빌드는 실행하지 않았으며 공식 SDK 수동 빌드 경로를 사용했습니다.

이번 APK의 새 개발 서명은 기존 1.0.3과 다릅니다. 기존 앱에서 프리셋을 JSON으로 내보내고 앱을 삭제한 뒤 1.0.4를 설치하고 프리셋을 가져오세요. 개인 키는 Git에 포함하지 않습니다. APK 해시와 인증서 지문은 `apk/README.md`에 기록합니다.

실기기 확인 순서:

1. 케이블을 연결하고 **장치 설정 → 식별 정보 읽기**에서 저장값과 사용자 지정 사용 여부를 확인합니다.
2. 제조사명·시리얼 번호에 테스트용 ASCII 값을 입력하고 저장합니다.
3. 양쪽 USB를 모두 분리하여 전원을 끊은 뒤 다시 연결합니다.
4. 앱에서 다시 읽은 값과 대상 PC의 USB 제조사명·시리얼 번호를 확인합니다. 제어 기기 쪽 시리얼 어댑터의 정보는 변경되지 않습니다.
5. 각 항목의 체크를 해제하고 저장·재연결하여 기본 문자열로 돌아가는지 확인합니다. 제품명·VID/PID·입력 기능과 통신 속도도 함께 확인합니다.

재실행은 README의 `npm test`, `npm run test:ui`, `scripts/test_native.py`, `scripts/build_apk.py`를 사용합니다.

호환 모드는 기존 개별 명령 경로를 사용합니다. DOM 검사에서 빠른 입력의 일괄 전송 사용, 호환 모드의 개별 누름·해제, 한글 전환·백그라운드 중지·키 해제, 압축 파일·UTF-8 변경분 복원을 확인했습니다.

## 실기기 속도 확인

실제 갤럭시·CH340/CH9329 장치가 연결되어 있지 않아 초당 입력 속도와 Android USB/WebView 실동작은 측정하지 못했습니다. 사용자가 보고한 기존 57600 bps, 빠르게 / 0ms의 PC 약 100자/초와 APK 약 35자/초는 변경 전 관측값이며 새 버전의 성능 수치가 아닙니다.

1. 기존 앱의 프리셋을 JSON으로 내보냅니다. 새 APK의 서명이 다르므로 기존 앱을 삭제하고 1.0.3을 설치한 뒤 가져옵니다.
2. 같은 케이블·대상 입력창·영문(A) 상태에서 57600 bps, 빠르게 / 0ms로 동일한 긴 영문 텍스트를 보내고 평균 속도를 비교합니다.
3. 대상 PC에서 누락·중복이 없는지 확인하고, 한글 혼합·중지·다시 연결·파일 디코더 검증을 확인합니다.
4. 실제 속도 개선 폭은 위 실측으로 판단합니다. PC 100자/초 도달을 보장하지 않습니다.

## 실기기 확인이 필요한 항목

이 환경에는 갤럭시나 USB 케이블이 연결되어 있지 않습니다. **APK를 실제 안드로이드에 설치·실행하거나 실제 USB 장치와 통신하는 검증은 하지 못했습니다.** 가상 장치는 Android USB Host·시스템 권한창·SAF 파일창·WebView 수명주기를 대신 검증하지 않습니다. DOM 테스트는 화면 레이아웃을 렌더링하는 시각 검사가 아닙니다.

설치 후 확인 순서:

1. 인터넷 없이 앱 화면이 열리는지 확인합니다.
2. OTG로 CH340을 연결하고 **USB 확인 / 권한**에서 장치 목록과 칩을 확인한 뒤 권한 요청을 허용합니다. 거부·분리·재연결도 확인합니다.
3. 대상 PC의 빈 입력창에서 `Hello 123!`를 전송합니다.
4. Windows 한국어 IME / 두벌식 / 101키 종류 1 / 영문(A) 상태에서 `안녕하세요 hello`를 전송합니다.
5. 마우스 기능이 있는 모드에서 클릭·이동을 확인합니다.
6. 짧은 한글 텍스트 파일을 대상 `decoder.html`로 보내고 CRC/SHA 검증 결과를 확인합니다.
7. 프리셋 내보내기·가져오기, 디코더 저장, 설정 백업을 확인합니다.
8. 긴 전송을 중지하고, 앱을 나갔다가 돌아와 키 해제·재연결을 확인합니다. IME 상태는 대상 PC에서 직접 확인합니다.
9. 새 디코더를 준비하고 수정 전·후 UTF-8 파일로 변경분을 전송한 뒤, 대상에서 같은 기준 파일을 선택해 검증·저장을 확인합니다.

## 재실행

```sh
npm install
npm test

```

USB 권한창 자체와 native USB 상태 창은 실제 Android에서 확인해야 합니다. 검사에 쓰인 USB 장치는 메타데이터 모델이며 실제 USB 열기·송수신 검증이 아닙니다. 이번 1.0.2는 새 로컬 개발 키로 서명했으며, 인증서가 기존 배포 1.0.1과 다름을 APK 검사로 확인했습니다. 업데이트 설치가 불가능하므로 프리셋을 내보낸 뒤 기존 앱을 삭제하고 설치해야 합니다. APK 해시와 인증서 지문은 `apk/README.md`에 기록했습니다.
